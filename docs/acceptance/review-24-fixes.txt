## 1. F1-1 客户端同步证据（RED → GREEN）

### 1.1 RED：只注入、不标脏时客户端收不到（旧实现的真实缺口）

首次运行（`GTSNLib_UI_AUTOTEST=machine`，`GtMachineDebug` 尚未调用 `onChanged`）：

```
[GTSNLib] machine autotest: placing gtsnlib:test_machine at BlockPos{x=-4, y=78, z=5}
[GTSNLib] machine autotest: client mirror present (energy=0/2048), charging 512 EU server-side
[GTSNLib] machine autotest: server executing 'gtsnlib debug charge -4 78 5 512'
[GTSNLib] machine autotest FAIL: client never received the synced energy value at BlockPos{x=-4, y=78, z=5}
    (server injected 512 EU; client energyStored=0) -- @DescSynced mirror read NOT proven
```

即：服务端能量改为 512，但 `NotifiableEnergyContainer.changeEnergy` 不标脏，客户端 `@DescSynced` 镜像
保持 0。**这说明原先「容量 2048」的同步证明确实是结论过强**。

### 1.2 GREEN：`onChanged` 后客户端观测到真实 0 → 512 跃迁

修复后 `GtMachineDebug.charge` 在写入后调用 `MetaMachine#onChanged()`；自动测试先排空到 0、等客户端
读到 0，再注入 512：

```
[GTSNLib] machine autotest: placing gtsnlib:test_machine at BlockPos{x=-4, y=78, z=5}
[GTSNLib] machine autotest: client mirror present (energy=512/2048), draining server-side to 0
[GTSNLib] machine autotest: server executing 'gtsnlib debug charge -4 78 5 -1000000'
[GTSNLib] machine autotest: client mirror reset to 0 EU, charging 512 EU server-side
[GTSNLib] machine autotest: server executing 'gtsnlib debug charge -4 78 5 512'
[GTSNLib] machine autotest: client received SYNCED energy 512/2048 (id=gtsnlib:test_machine tier=1 status=UNKNOWN)
[GTSNLib] machine autotest PASS: screen shows gtsnlib:test_machine tier=1 energy=512/2048 status=UNKNOWN
[GTSNLib] machine autotest grabbing screenshot gtsnlib-ui-machine-status.png (window=1280x720 target=1280x720)
[GTSNLib] machine autotest finished (DONE), stopping client
BUILD SUCCESSFUL
```

### 1.3 调试入口

`/gtsnlib debug charge <x> <y> <z> <eu>`（服务端命令，权限 ≥ 2）→ `GtMachineDebug.charge(Level, BlockPos, long)`。
